# Своя Игра UNIST — спецификация

Дата: 2026-10-03
Статус: черновик на ревью

## 1. Цель

Живая викторина в формате «Своей игры» для ~60 русскоязычных студентов UNIST в одной комнате.
Ведущий показывает табло на проекторе, каждый игрок отвечает со своего телефона (Kahoot-стиль, 4 варианта).
Длительность игры — 10–15 минут.

**Успех:** 60 человек подключаются по QR за ~2 минуты, игра проходит без зависаний и споров
«кто первый», в конце на экране понятный победитель.

## 2. Формат игры

- **Табло:** 4 темы × 3 вопроса (100 / 200 / 300) = 12 вопросов, один раунд, без финала.
- **Темы:** UNIST · Русские мемы · English memes · TikTok-мемы.
- **Язык:** каждый вопрос и каждый вариант показываются на двух языках — RU и EN.
- **Ответ:** 4 варианта (красный ▲, синий ◆, жёлтый ●, зелёный ■). Один ответ, изменить нельзя.
- **Таймер:** 15 секунд. Вопрос закрывается раньше, если ответили все, кто может отвечать.
- **Очки (классика «Своей игры»):** верно — `+стоимость`, неверно — `−стоимость`, нет ответа — `0`.
  Счёт может быть отрицательным. Бонуса за скорость нет. Ставок нет.
- **Кто выбирает клетку («выбирающий»):** самый быстрый из ответивших верно на предыдущий вопрос
  (по времени получения ответа сервером). Если выбирающего нет (первый вопрос или никто не ответил
  верно) — клетку выбирает ведущий сам. Выбирающий говорит клетку вслух, кликает всегда ведущий.
- **Мем в мешке:** одна клетка помечена в `questions.json` как `bag: true`; на табло она выглядит как обычная.
  При открытии показывается заставка «Мем в мешке!». Отвечает только «адресат» — текущий выбирающий;
  если выбирающего нет — случайный подключённый игрок. Стоимость ×2 (в обе стороны).
  У остальных на телефоне «Смотрим: отвечает <имя>». Если адресат ответил верно — он выбирает следующую клетку,
  иначе выбирающего нет.
- **Досрочный конец:** ведущий может в любой момент нажать «Завершить игру» → финальный рейтинг.

## 3. Экраны

### 3.1 `/host?key=<HOST_KEY>` — проектор (ведущий кликает мышью)

| Фаза | Что видно | Действия ведущего |
|---|---|---|
| Лобби | Название, QR-код и короткая ссылка на `/play`, число игроков, облако имён | «Начать игру» |
| Табло | Сетка 4×3, сыгранные клетки погашены; «Выбирает: <имя>» или «Выбирает ведущий»; мини-топ-5 сбоку | Клик по клетке |
| Мешок (заставка) | «Мем в мешке! Отвечает <имя>, ×2» — 3 секунды | — (авто) |
| Вопрос | Тема и стоимость, вопрос RU/EN, картинка (если есть), 4 цветных варианта RU/EN, таймер, «Ответили 42/60» | «Закрыть досрочно» |
| Разбор | Правильный вариант подсвечен, под каждым вариантом — сколько выбрали, «Быстрее всех верно: <имя>», топ-5 с изменением очков | «К табло» |
| Финал | Подиум топ-3 + места 4–10 | — |

Всегда доступна кнопка «Завершить игру» (с подтверждением на странице, не через `confirm()`).

### 3.2 `/play` — телефон игрока

| Фаза | Что видно |
|---|---|
| Вход | Поле «Имя», кнопка «Войти» (имя 1–20 символов) |
| Ожидание | «Ты в игре, <имя>! Смотри на экран», текущий счёт и место |
| Вопрос | 4 большие цветные кнопки во весь экран, на каждой фигура + текст варианта (RU/EN), таймер |
| Ответ принят | «Ответ принят, ждём остальных» |
| Мешок, не адресат | «Смотрим: отвечает <имя>» |
| Результат | «+200» / «−200» / «0 — не ответил», правильный ответ, счёт и место |
| Финал | Итоговое место и счёт |

## 4. Архитектура

```
svoya-igra/
  package.json          # express, socket.io, qrcode; node:test для тестов
  server.js             # HTTP + Socket.IO; тонкий слой: события ↔ вызовы Game
  src/game.js           # вся логика игры, без сети и таймеров (чистый класс)
  src/questions.js      # загрузка и валидация questions.json
  questions.json        # 12 вопросов
  public/
    host.html, host.js, play.html, play.js, style.css
    img/                # картинки к вопросам
  test/game.test.js     # юнит-тесты логики
  test/questions.test.js
  scripts/bots.js       # нагрузка: 60 ботов через socket.io-client
  docs/spec.md
```

**Принцип:** `Game` ничего не знает о сокетах и времени. Сервер передаёт ему действия и текущее время
(`now`), а таймер 15 с живёт в `server.js` и по истечении вызывает `game.closeQuestion(now)`.
Это делает логику полностью тестируемой.

### 4.1 Game — состояние и методы

Состояние: `phase` (`lobby | board | bag_intro | question | reveal | final`), `players`
(`id → {name, score, token, connected}`), `played` (множество клеток), `chooserId`,
`current` (клетка, вопрос, адресат мешка, `openedAt`, ответы `{playerId → {option, at}}`).

Методы:
- `join(name, token?)` → игрок (новый или восстановленный по токену); дубли имён получают суффикс « 2», « 3».
- `start()` — лобби → табло.
- `openCell(theme, value, now)` — табло → вопрос (или → заставка мешка с назначением адресата).
- `beginBagQuestion(now)` — заставка → вопрос.
- `answer(playerId, option, now)` — принимает первый ответ от допустимого игрока в фазе вопроса; иначе игнор.
- `allAnswered()` — ответили все подключённые допустимые игроки.
- `closeQuestion(now)` — начисляет очки, определяет нового выбирающего, → разбор; возвращает итоги.
- `toBoard()` — разбор → табло, либо → финал, если все клетки сыграны.
- `end()` — → финал из любой фазы.
- `hostView()` / `playerView(playerId)` — снимки состояния для отправки клиентам.

Правильный ответ **не** попадает в `playerView`, пока фаза не `reveal`.

### 4.2 Сетевые события (Socket.IO)

Клиент → сервер:
- игрок: `join {name, token}`, `answer {option}`
- ведущий (только при верном `HOST_KEY` в handshake): `start`, `open {theme, value}`, `close`, `board`, `end`

Сервер → клиент:
- `state` — полный снимок для своей роли (ведущему — `hostView`, каждому игроку — его `playerView`)
  рассылается после каждого изменения. 60 игроков × маленький JSON — без проблем.
- `joined {playerId, token}` — игроку после входа; токен хранится в `localStorage` телефона.

### 4.3 Переподключение

Телефон хранит `token` в `localStorage` и при каждом подключении шлёт `join` с ним — игрок возвращается
с тем же счётом и именем. Отключённый игрок остаётся в рейтинге; в «Ответили N/M» и в `allAnswered`
учитываются только подключённые. Ведущий при перезагрузке страницы просто получает свежий `state`.

### 4.4 Формат `questions.json`

```json
{
  "title": "Своя Игра UNIST",
  "themes": [
    {
      "name": { "ru": "UNIST", "en": "UNIST" },
      "questions": [
        {
          "value": 100,
          "text": { "ru": "Столица Южной Кореи?", "en": "What is the capital of South Korea?" },
          "options": [
            { "ru": "Сеул", "en": "Seoul" },
            { "ru": "Пусан", "en": "Busan" },
            { "ru": "Ульсан", "en": "Ulsan" },
            { "ru": "Тэгу", "en": "Daegu" }
          ],
          "correct": 0,
          "image": null,
          "bag": false
        }
      ]
    }
  ]
}
```

Валидация при старте сервера (сервер не стартует при ошибке, сообщение указывает на вопрос):
ровно 4 варианта, `correct` ∈ 0..3, у текста и вариантов есть `ru` и `en`, ровно одна клетка `bag: true`,
стоимости в теме уникальны, картинка (если указана) существует в `public/img/`.

Начальное наполнение — 12 вопросов из брейншторма (см. раздел 8).

## 5. Ошибки и крайние случаи

- Ответ после закрытия, повторный ответ, ответ не-адресата мешка, некорректный `option` — молча игнорируются.
- Клик по сыгранной клетке или вне фазы табло — игнор.
- Адресат мешка отключился — вопрос идёт по таймеру, он получает 0, выбирающего нет.
- Мешок без подключённых игроков (никого нет) — адресат не назначается, вопрос показывается, очков нет.
- Пустое имя / >20 символов — ошибка на телефоне, вход не выполнен.
- Перезапуск сервера (Render) теряет состояние — принимаем риск: игра 15 минут, состояние в памяти.
- Страницы не используют `alert/confirm/prompt`.

## 6. Деплой

- **Основной:** Render.com, бесплатный Web Service из GitHub-репозитория. `npm start`, переменные окружения
  `HOST_KEY` (секрет ведущего) и `PORT` (даёт Render). Публичный адрес для QR берётся из заголовков запроса
  страницы ведущего.
- Free-инстанс засыпает после 15 мин без трафика и просыпается ~1 мин — ведущий открывает `/host` за 2+ минуты до начала.
- **Запасной:** ноутбук — `npm start` + `cloudflared tunnel --url http://localhost:3000`.
- Краткая инструкция в `README.md`.

## 7. Тестирование

- **Юнит-тесты `Game` (node:test):** очки +/−/0; повторный ответ игнорируется; выбирающий = самый быстрый верный;
  нет верных → выбирает ведущий; мешок: адресат, ×2 в обе стороны, остальные не могут отвечать;
  `allAnswered` учитывает только подключённых; переподключение по токену сохраняет счёт; дубли имён;
  после 12 клеток → финал; `end()` из любой фазы; `playerView` не раскрывает правильный ответ до разбора.
- **Валидация вопросов:** тест на реальном `questions.json` и на сломанных примерах.
- **Нагрузка `scripts/bots.js`:** 60 ботов подключаются к указанному URL, отвечают случайно с задержкой 1–10 с;
  прогон локально и на Render, проверка что все ответы учтены и задержки рассылки < 1 с.
- **Ручная проверка:** 2–3 настоящих телефона + проектор/второе окно перед мероприятием.

## 8. Вопросы

Настоящие вопросы игры хранятся **вне репозитория** — в `questions.json` (в `.gitignore`), чтобы игроки
не прочитали ответы на GitHub. В репозитории лежит `questions.json.example` с той же структурой
(4 темы × 3 вопроса, один «Мем в мешке»); на нём работают тесты. На Render файл загружается как Secret File.

## 9. Вне рамок

Аккаунты, редактор вопросов в браузере, несколько раундов, финал со ставками, «Аукцион»,
бонус за скорость, кик игроков, сохранение истории игр, несколько параллельных комнат.
